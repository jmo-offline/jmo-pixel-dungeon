## Approach and key decisions

1. **Fix pixel scaling first.** Every later step gets judged from screenshots, and fractional zoom makes 16px art shimmer and smear. That would hide both the gains and the regressions. My pick is to keep `canvas_items` so text stays sharp. Zoom snaps to whole numbers (2x to 5x; keep the lerp, but snap it to an integer when it settles). The camera's global position rounds to `1/zoom` of a pixel, and the HUD gets one uniform scale, `min(sx, sy)`. I'm not switching to `viewport` stretch: it would blur the pixel font from PR #27 and break the mobile HUD hit-testing in `hud.gd:328-346`.
2. **Do the cheap swaps before the big rendering change.** Trap and plant art, animated water, softer fog and floor variation are each about a one-file change with no layout risk. Raised walls is the biggest visual win, but it adds a layer above the sprites and changes how fog reads at wall edges, so it goes after the cheap steps, once there are clean before/after screenshots to compare against.
3. **Port SPD's logic, not just its pictures.** Raised walls should follow `DungeonTileSheet.getRaisedWallTile` / `stitchInternalWallTile` and `DungeonWallsTilemap` (the overhang drawn on the cell above each wall, z-ordered above characters). Floor variation should follow `DungeonTileSheet.getVisualWithAlts`, using a per-cell variance seeded from the level, so the floor doesn't reshuffle on reload. Each PR should cite the upstream Java the same way `trap_sprite.gd` already does.
4. **Keep `EffectManager`'s API.** All 31 call sites keep working. `particle_burst` starts drawing SPD-style square pixel particles instead of circles, and new calls (`speck(pos, type, count)`, `missile(from, to, item)`) get adopted at the call sites that have an SPD equivalent. There's no mass rewrite.
5. **Keep procedural fallbacks.** Every texture lookup keeps today's drawing as the fallback when an index or sheet is missing, matching the existing `TerrainVisuals._create_fallback` pattern.
6. **Verify every step with screenshots.** Each PR runs the headless tests (`godot --headless --path . -s res://tests/run_tests.gd`) and attaches before/after captures. PR #27 adds `tools/capture_screenshots.gd`, so the steps that need captures should branch after #27 merges, or from `claude/project-thread-m6fnvm` if it hasn't. Tests cover the logic only: tile index choice, the trap and plant atlas index, fog state encoding, and integer zoom snapping.

## Overlaps with other elements

- **Bosses:** the arena tile sets (step 10) belong to the boss floors, so step 10 should land with or after the bosses element's arena work rather than race it.
- **Controls:** the hover cursor and path preview (Tier 4) need the integer-scaled camera from step 1 to look right, so the controls element should come after step 1.
- **Level variety (#15):** it isn't in this element. Step 5's floor variation is the only visual part of it.

## Ordered steps (one PR each)

1. **Pixel-perfect scaling.** _Shipped as [PR #31](https://github.com/jvmisxn/jmo-pixel-dungeon/pull/31) (2026-10-14, awaiting merge). It snaps the displayed zoom to whole screen pixels with window stretch included, and rounds the camera position and shake to the pixel grid. It doesn't use the snap project setting. The HUD's uniform scale moved to step 9._ Original scope: Integer-only camera zoom, with steps 2-5x and a mobile minimum of 2. Round the camera position to the pixel grid, set `rendering/2d/snap/snap_2d_transforms_to_pixel`, and give the HUD a uniform scale. Files: `project.godot`, `src/scenes/game_camera.gd`, `src/ui/hud.gd` (`_sync_canvas_layer_scale` only). Tests: zoom snapping and the HUD scale stays uniform. Update `test_mobile_hud_input` if it assumes non-uniform scale.
2. **Real trap and plant art.** `TrapSprite` and `PlantSprite` draw from `terrain_features.png` (`color + shape*16` for traps, `112 + Plant.image` for plants), and inactive traps use the BLACK column. Check each plant's image index against upstream `Plant.java` before mapping it. The procedural drawing stays as the fallback, and the info windows pick up the art for free. Files: `src/sprites/trap_sprite.gd`, `src/sprites/plant_sprite.gd`, `tests/cases/test_trap_sprites.gd` and a new plant atlas test.
3. **Animated water.** Replace the per-cell water tile layer with one full-map quad that repeats the 32x32 region water texture, under the terrain layer, with a small shader that scrolls it slowly the way SPD does. The stitched water edge tiles (indices 32-47) already leave the water area transparent. Files: `src/tiles/tile_map_manager.gd`, plus a new `water.gdshader`, and drop the dead water helpers in `terrain_visuals.gd`.
4. **Softer fog.** Encode mapped separately from visited, and give mapped SPD's darker, cooler tint. Only apply distance dimming when `is_dark` is set. Ease state changes over about 0.15s by keeping the previous fog texture and mixing it with the current one through a uniform. Files: `src/tiles/fog_of_war.gd`, `src/tiles/fog_of_war.gdshader`. Test: the state encoding for unseen, mapped, visited and visible.
5. **Floor and grass variation.** Per-cell variance seeded by the level seed and the cell, choosing `FLOOR_DECO` and the `*_ALT` floor, grass and embers tiles at SPD's rates. Files: `src/tiles/spd_tileset.gd` (constants), `src/tiles/tile_map_manager.gd`. Test: the same seed and cell always give the same tile.
6. **Raised walls.** Port the raised wall faces, internal wall stitching, raised doors (including sideways doors) and the raised statue, bookshelf and high-grass tiles. Add a `WallsLayer` TileMapLayer for the overhangs, placed above the entity layer and below effects and fog. Match SPD's fog rule that a wall face is seen from the cell below it. Files: `spd_tileset.gd`, `terrain_visuals.gd`, `tile_map_manager.gd`, and the layer setup in `game_scene.gd` (around lines 1040-1046). Tests: tile choice for a wall over floor, wall over wall, and the door orientations. This is the largest step. If the diff gets too big, split it into walls and doors first, then the overhang layer.
7. **SPD pixel particles and specks.** `ParticleBurst` draws 1-2px squares that shrink, like SPD's PixelParticle. Add `EffectManager.speck(pos, type, count)` backed by `specks.png`, and use it where SPD does: healing (HEALING), level-up (UP/STAR), charm (HEART), gold pickup (COIN), confusion (QUESTION) and sleep (NOTE). `ring_effect` uses the ripple from `effects.png`. Files: `src/effects/particle_burst.gd`, `effect_manager.gd`, a new `speck_effect.gd`, and the matching call sites.
8. **Real projectiles.** A thrown item flies as its own `items.png` icon (weapons spin and arrows point along the path, like `MissileSprite`). Wand bolts become colored pixel-particle trails per wand (`MagicMissile`), and the fire wand uses the fireball sheet. This also replaces the beige thrown-item dot. Files: `src/effects/projectile_effect.gd`, `effect_manager.gd`, and the 4 `shoot_projectile` call sites.
9. **SPD HP, shield and EXP bars, and a uniform HUD scale.** Make `hud.gd` `_sync_canvas_layer_scale` uniform (carried over from step 1), then rebuild the HUD status bars from the `status_pane.png` strips with `UIUtils.atlas_texture`, and delete the hidden `StatusPane` and its update calls once nothing reads it. This waits for PR #27. Files: `src/ui/hud.gd`, `src/ui/status_pane.gd` (removed), and the HUD tests.
10. **Arena and variant tile sets.** Use `custom_tiles/*` on the boss and quest floors, and the crystal and gnoll caves sheets where SPD uses them. This is coordinated with the bosses element. Files: `spd_tileset.gd`, `tile_map_manager.gd`, and the boss level classes.
